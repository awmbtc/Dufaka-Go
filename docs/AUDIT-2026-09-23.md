## 已修复

### 支付、订单和库存

1. 微信 APIv3 通知的 `associated_data`、`out_trade_no`、`trade_state`、`transaction_id` 缺失 JSON 标签，导致无法按真实载荷解密/发货。已修复，并用本地 RSA 签名和 AES-GCM 密文走完整通知处理；伪造签名被拒绝，重复通知幂等。
2. cldx 首次报价与付款截止时间原子锁定在订单；刷新和并发打开不再改价、延长有效期。App 链接使用固定 scheme 与编码后的参数生成，解决 Go 模板把 `clodex://` 过滤成无效地址。
3. cldx 同步纳入已过期且有报价的订单，查询状态时先核对到账，解决过期后到账无法进入发货的问题。过期时保持原始应付金额，避免已支付优惠价被判金额不一致。人工订单过期后付款会重新扣库存。
4. 已支付/过期订单不再生成新的收款码；停用支付渠道不能继续进入收银台。启动时不再自动重新启用店主已停用的 cldx 渠道。
5. 修复本机订单 Cookie 中原始 JSON 引号被处理坏的问题；改为 URL-safe Base64 + HMAC，并限制保存最近 40 单。防止自行篡改 Cookie 绕过查询密码。本人下单浏览器可正常查看，其他浏览器仍需查询密码。
6. 查询订单号的入口补上查询密码字段和参数传递。补足支付处理异常、查询网络失败时的提示。
7. 后台不能把未付款订单直接改成“处理中”绕过支付；订单状态保存增加旧状态条件，避免覆盖同时到达的支付结果。已售/订单占用卡密不能被直接编辑或删除，防止破坏预留库存。
8. 后台写入增加浏览器来源校验。已写入安装配置的站点数据库不可用时返回 503，不重新开放安装入口。极验尚未接通服务端验证时明确拒绝下单，不能靠伪造非空字段通过。
9. 首页商品库存改为随商品查询计算，移除每个商品额外查库存；分类与邮箱查询先释放结果集再查询详情，减少连接池占用。微信请求增加超时。

### 前台显示与功能

- cldx 收银页分别使用三套主题自己的页面结构，修复 Luna 中混用 Bootstrap 布局的问题。
- 商品详情、公告、页脚恢复富文本显示，使用 HTML 白名单清洗，不将脚本或事件属性直接输出。
- Luna 补回手机公告与购买页查单入口；购买数量和支付选择改为可键盘操作的按钮。
- Unicorn、Hyper 补批发价格、购买提示；Hyper 补原价和限购；Luna/Hyper 确认页补优惠信息，Hyper 确认页恢复居中栏宽。
- Unicorn 订单详情恢复信息/发货内容分栏、邮箱、时间、复制和继续支付；Hyper 补复制与继续支付。
- 缺货或没有支付渠道的购买页禁用提交并提示原因。下架商品不能直接进入购买页。
- 补图片宽度、富文本换行、键盘焦点样式；取消 Luna 禁止缩放设置。Hyper 支付名称用文本节点插入，避免名称被当作 HTML 执行。
- 修复复制失败仍提示成功的问题。首页不再将人工商品也宣称为自动发货。

### 后台显示

- 订单筛选字段 `Title` 覆盖页面标题，导致订单列表标题为空或变成搜索词；改为独立 `FilterTitle`。
- 手机导航增加展开状态、打开后聚焦和 Escape 关闭；复制提示与实际结果保持一致。
- 继续使用原有侧栏、圆角分组、浅色/深色/跟随设置及 macOS 风格。未替换后台主题。
