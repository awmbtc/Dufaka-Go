## 高优先级（先修）

1. **依赖与工具链漏洞可达**。`github.com/jackc/pgx/v5 v5.7.4`（GO-2026-5004，占位符与美元引号混淆导致 SQL 注入；本项目 SQL 都是常量文本，实际可利用性低但应升 ≥5.9.2）、`golang.org/x/text v0.21.0`（GO-2026-5970 无限循环，经 pgx 连接路径可达）、`golang.org/x/net v0.26.0`（GO-2026-5026）、Go 标准库 1.26.5 六项（html/template JS 上下文、net/http 头超时、crypto/tls 握手、net/url、encoding/xml、encoding/asn1，均在 1.26.6 修）。修法：`go get -u ./... && go mod tidy`，用 Go ≥1.26.6 重新构建部署。
2. **线上静态目录可列目录并暴露部署垃圾文件**。`internal/httpx/server.go:115` 用 `http.FileServer(http.Dir("web/assets"))`，没有关闭目录索引；线上已确认列出 `._*` AppleDouble 文件（从 Mac 用 cp/rsync 上传所致）。修法：包一层拒绝以 `/` 结尾的路径或用只读 FS 去掉索引；服务器上 `find web/assets -name '._*' -delete`，以后用 `rsync --exclude '._*'` 或 `COPYFILE_DISABLE=1`。
3. **cldx 同步无界轮询**。`internal/store/cldx.go:35-39` `WaitingSNs` 取 `status IN (1,-1) AND cldx_minor IS NOT NULL` 的全部订单，没有时间窗；`cmd/dufaka/main.go:58-68` 每 30 秒串行逐单调钱包（每次最长 8 秒超时）。过期 cldx 订单只增不减，迟早一轮超过 30 秒，`ExpireDue` 随之延后，钱包请求量单调上涨。修法：只轮询 `cldx_expires_at > now() - 宽限期`（例如 24 小时）的过期单，超出宽限期的转人工对账；轮询加总时限并并发有界。
4. **`buy_ip` 记的是 nginx 的地址**。`server.go:247` 用 `r.RemoteAddr`，经 nginx 后永远是 `127.0.0.1:端口`，后台订单页的 IP 和以后的风控都没用。修法：只信任本机代理时解析 `X-Real-IP` / `X-Forwarded-For` 第一段，nginx 配置对应 `proxy_set_header`。
5. **微信支付配置两处来源，后台字段部分无效**。`internal/pay/wechat.go:27-45,92`：下单用后台支付行的 `merchant_pem`（私钥）和 `merchant_id`，但 `appid`、证书序列号、平台公钥 ID 只读环境变量，后台填的「商户 KEY」被 `_ = apiV3` 丢弃；通知解密 `server.go:416` 只读 `WECHAT_PAY_API_V3_KEY` 环境变量。店主在后台改了 KEY 不生效，环境变量缺一个就解密失败→返回 400→微信持续重试→订单永远不完成且无日志。修法：定一个真源（建议全部落后台支付行，或全部环境变量并在后台只读展示），并在收银台前做一次配置完整性自检。
6. **`/cldx/pay` 与 `/cldx/{id}` 是到 App scheme 的开放跳转**。`internal/httpx/cldx.go:69-76` 把任意 query 原样拼进 `clodex://pay?`。攻击者可以做一个 `https://shop.clodex.lol/cldx/pay?to=攻击者&amount=…&order=受害人订单号` 的链接或二维码，域名可信、参数却是攻击者的。修法：只接受订单号，服务端按订单锁定的 `to`/`cldx_minor`/`cldx_expires_at` 重建参数再跳转，其余一律 404。

## 中优先级

7. **后台无法编辑或停用 cldx 渠道**。`internal/admin/sales.go:575-580` 要求商户 ID 和商户密钥非空，而 `internal/store/cldx.go:8` 种子行两者都是空字符串，保存时报「请填写商户 ID」。店主要停用只能填假值。修法：`pay_check == "cldx"` 时跳过这两项校验，或种子时写占位说明。
8. **「开启图形验证码」是空开关**。设置页有 `is_open_img_code`（`system.go:193`），但下单 `store.go:228-244` 不校验、三套模板也没有 `img_verify_code` 输入框；而 `is_open_geetest` 打开则直接拒绝所有下单。两个开关的行为都会让店主误判。修法：未接通的开关在设置页禁用并标注。
9. **过期后到账，优惠码被用两次**。`ExpireDue`（`store.go:556`）退回优惠码次数，`Complete` 对 `status=-1` 的订单（`store.go:453`）不再扣回。上一轮报告已列为待定规则，仍未落实。
10. **预留卡密可能永久占用**。`Complete` 的取卡 SQL（`store.go:457-462`）用 `FOR UPDATE SKIP LOCKED`：本单预留的卡若恰好被别的事务锁住就被跳过、改发另一张，而被跳过那张的 `reserved_order_id` 仍指向已完成订单，前台库存永远少一张。修法：发货成功后 `UPDATE carmis SET reserved_order_id=NULL WHERE reserved_order_id=$订单id AND status=1`。
11. **已付款但库存不足（状态 6）的订单没有自动补发路径**。cldx 轮询只看 1/-1；后台订单页只能改状态，不能触发发货（`sales.go:405-460`）。店主补了卡后要自己想办法。修法：后台加「重新发货」动作调用 `Complete` 幂等路径，或轮询纳入状态 6。
12. **不开查询密码时，凭邮箱可查到卡密**。`server.go:316-329` + `store.go:395`：只要知道买家邮箱就能拿到其最近 20 单含卡密原文。这是原站行为，但对 Clodex 小店是真实泄露面；建议默认开启查询密码，或邮箱查询只列订单号不显示卡密。
13. **查询密码走 URL query**。`server.go:313` 把 `search_pwd` 放进 `?pwd=` 重定向，会进 nginx 访问日志和浏览器历史。改为 POST 直接渲染或走一次性 cookie。
14. **后台登录无限速、无锁定**，且用户不存在时不做 bcrypt 比较（`auth.go:55-65`），可按响应时间枚举用户名。修法：统一做一次假 bcrypt，按 IP/账号限速。
15. **安全响应头缺失**（线上已核实）：无 HSTS、X-Frame-Options、CSP。可在 nginx 加。
16. **错误静默**：`main.go:65` 丢弃 `ExpireDue` 错误，`SyncCldx` 和 `syncCldxOrder` 任何失败都不记日志。出问题时运维看不到。最少 `log.Printf`。
17. **每个请求多做 2-4 次数据库读**：`guard` 每次请求 `SELECT count(*) FROM admin_users`（`server.go:108-111`），`Site()` 每次读整张 `settings` 且一个页面调多次（`server.go:216,226-227`）。加 5-30 秒缓存即可。
18. **收银页每 5 秒轮询一次都会打一次钱包接口**（`cldxpay.html` + `server.go:293-295`）。小流量无所谓，上量前给单订单加最短查询间隔。
19. **330 行支付驱动是死代码**：`internal/pay/pay_drivers.go` 的易支付/码支付/Payjs/Paysapi/V 免签函数没有任何非测试调用；后台又允许新增这些渠道，顾客选中后在 `server.go:378-380` 撞到「还没有接通收银台」。要么接通，要么后台只允许 `wescan`/`cldx`，并删掉死代码。
20. **后台商品列表库存口径与前台不同**：`catalog.go:74-76` 数所有未售卡，前台 `store.go:140` 排除已预留的。店主会看到比顾客多的库存。
21. 微信通知验签没有核对 `Wechatpay-Serial` 与所配平台公钥是否一致（`wechat.go:132`），平台证书轮换时会静默全拒。
22. 后台 CSRF 只靠 `Origin`/`Sec-Fetch-Site`（`server.go:149-156`），`same-site` 放行，意味着 `*.clodex.lol` 下任何子域都能跨站提交后台表单。低风险，加 CSRF token 更稳。
23. cldx 成交的 `trade_no` 写的是 `cldx:<订单号>`（`cldx.go:94`），不是钱包侧付款 ID，退款对账要再查一次钱包。

## 部署清单（线上 shop.clodex.lol）

1. 备份：`pg_dump -Fc "$DUFAKA_DATABASE_URL" -f dufaka-pre-audit-$(date +%F).dump`，保留旧二进制以便回滚。
2. 编译：Go ≥ 1.26.6，`CGO_ENABLED=0 GOOS=linux GOARCH=<服务器架构> go build -trimpath -o dufaka ./cmd/dufaka`。
3. 迁移（启动新程序前）：`psql -v ON_ERROR_STOP=1 -f sql/002_cldx_quote.sql`，再 `psql -v ON_ERROR_STOP=1 -f sql/003_cldx_poll.sql`（不能包在事务里，含 `CONCURRENTLY`）。核对 `idx_orders_cldx_live`、`idx_orders_cldx_late` 都是 `indisvalid=t`。
4. 环境变量：`DUFAKA_BASE_URL=https://shop.clodex.lol`、`DUFAKA_SESSION_KEY`、`DUFAKA_ADDR=127.0.0.1:8080`；微信 `WECHAT_PAY_APP_ID`、`WECHAT_PAY_CERT_SERIAL_NO`、`WECHAT_PAY_PLATFORM_KEY`、`WECHAT_PAY_API_V3_KEY`（32 字节），建议加 `WECHAT_PAY_PLATFORM_SERIAL` 或 `WECHAT_PAY_PUBLIC_KEY_ID`；钱包 `WALLET_MERCHANT_SECRET`、`WALLET_MERCHANT_ID`。nginx 不在本机时设 `DUFAKA_TRUSTED_PROXIES`。
5. nginx：按 `docs/nginx-shop.conf.example` 加 `proxy_set_header Host / X-Real-IP / X-Forwarded-For / X-Forwarded-Proto`，`nginx -t && systemctl reload nginx`。
6. 静态文件：`find <部署目录>/web/assets -name '._*' -delete`；以后上传用 `rsync --exclude '._*'`。
